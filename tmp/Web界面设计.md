# Meloport 网页界面设计

更新日期：2026-11-20

## 设计依据

本轮界面检索重试后没有得到可直接采用的匹配方案，因此采用通用管理控制台规范，围绕真实任务数据、清晰状态和键盘操作实现，不编造额外设计检索结果。

目标是本机单用户歌单同步管理，不加入播放器、远程账户或密钥粘贴流程。使用内嵌静态资源，不加载外部字体、图标或前端服务。

## 视觉与结构

- 深绿侧栏、浅色工作区、青绿色主要动作；系统字体栈覆盖 Windows 与中文。
- 侧栏分为任务概览、歌曲检索、运行记录和系统设置。
- 概览先显示任务／启用／下载登记／大小统计，再呈现任务、来源、有效计划、最近与下次执行状态。
- 新建／编辑、歌单预览和删除确认使用明确的模态对话框；危险动作使用单独颜色与文字。
- 小屏将侧栏变为顶部导航，将密集表格转换为卡片式数据，保留字段标签和操作按钮。

## 交互与可访问性

表单使用可见标签，明确区分全局继承与任务覆盖；所有按钮有文本或可访问名称。提供跳转主内容、可见焦点、键盘对话框操作、错误提示与加载状态。状态同时使用文字，避免只凭颜色理解。

请求提交期间禁用重复操作；错误以当前位置可见信息呈现。网络失败不清空用户输入，也不显示伪造成功数据。未配置 Key 时解释原生搜索／预览仍可使用，下载解析才需要在环境中配置。

任务 ID 在更新时只读，运行中任务不允许编辑／删除。删除只移除订阅，不删除音频。API Key 和平台 Cookie 不进入页面输入、页面脚本存储或配置编辑请求。

## 验证结果

2026-11-20 已在实际 Go 二进制、隔离配置和 SQLite 上完成 67 项浏览器检查：桌面 1440×1100 为 40 项、手机 375×1000 为 8 项、手机长页 375×2100 为 8 项、横屏 812×450 为 8 项、可信 Escape 键与焦点恢复为 3 项。

前端开发可运行 `scripts/dev.ps1 -Action dev -Config config.yaml`，服务从受限的源码资源目录按请求读取三个白名单文件，刷新浏览器即可查看 HTML、CSS 和 JS 修改；生产启动仍使用嵌入资源。

其中 9 次任务／设置写操作直接使用 Go HTTP API，验证空任务、新建／编辑／删除、启用开关、错误保留输入和真实进程重启后的持久化。删除订阅后本地哨兵文件仍在；未配置 Key，没有产生真实下载或任务运行。4 次检索与 1 次预览使用明确的本地模拟响应，用于验证加载、分页、错误、来源显示和安全文本渲染；这部分不作为真实平台调用的证明。

已目视检查桌面与手机长页，开关及 44px 目标区域正常，任务卡片和操作按钮无横向溢出。截图及 JSON 检查结果在 `.cache/webui-qa/`，不纳入 Git。所有测试拥有的 Go 进程、隔离 Chromium、临时代理和调试端口均已清理，并验证端口可重新绑定。
