# Meloport 初始化设计

更新日期：2026-11-20

## 目标与接入范围

按歌单链接或 ID 订阅歌曲，定时补下载本地缺少的音频。所有任务继承全局时间，也可单独覆盖；不因远端删歌或删除任务而删除本地文件。使用本机 Go 服务、内嵌网页和 SQLite，Docker 包装留到后续。

正式平台限定为 ChKSz 支持的网易云、QQ 音乐、酷狗。歌单、搜索和歌曲元数据尽可能直接读取音乐平台；ChKSz 主要负责音频地址解析。其他平台只保留 `provider.Source` 扩展接口，不注册未实现适配器，不在配置或网页中展示为可用平台。

## 分层与回退

```text
平台歌单链接／ID
  → 原生平台歌单与详情（网易云 / QQ / 酷狗）
  → 完整性校验、去重和本地文件检查
  → 仅缺失文件进入 ChKSz 音频解析
  → 下载原子提交与 SQLite 登记
```

元数据默认直连，取消或成功空结果不回退。可选 `metadata.fallback_to_api` 默认开启：原生网易云歌单失败时，可用 ChKSz 网易云歌单接口；三平台原生搜索失败时，可用对应 ChKSz 搜索。QQ、酷狗没有文档化 ChKSz 歌单接口，失败时不得编造替代路径。

关闭元数据回退不影响音频解析；酷狗解析前取得 ChKSz 自身 ID 的搜索也属于音频解析步骤。回退会记录原因，歌单结果及同步摘要区分原生来源和 ChKSz 回退。

| 模块 | 职责 |
| --- | --- |
| `cmd/meloport` | 入口与终止信号 |
| `internal/config` | 严格 YAML、默认值、路径／平台／cron 校验、首次空配置和保留注释的编辑 |
| `internal/platform` | 有界、串行、凭据隔离的原生 HTTP，以及三平台歌单／搜索适配器 |
| `internal/provider` | 原生优先、文档化回退、酷狗身份确认和音频解析分流 |
| `internal/chksz` | 延迟读取 Key、请求间隔、错误脱敏和三平台音频解析 |
| `internal/app` | CLI、任务队列、调度、管理接口和健康检查 |
| `internal/webui` | 内嵌静态网页，无额外前端开发服务器 |
| `internal/syncer` | 平台独立的元数据读取／音频解析接口、增量同步和结果汇总 |
| `internal/download` | 流式下载、格式识别、大小限制、临时文件和原子发布 |
| `internal/state` | SQLite 下载登记、任务历史和统计 |

## 歌曲身份与完整性

- 网易云使用字符串歌曲 ID，`trackIds` 为完整成员依据；内嵌详情不足时按 ID 有界批量补齐。
- QQ 使用字符串 MID，对歌单进行固定页大小串行读取，检查总数、重复页和缺失成员，不混用数值 song ID。
- 酷狗区分分享码、special ID、gcid、chain；读取原生 hash，复用完整内嵌元数据，仅为缺失详情有界批量补齐，稳定文件身份优先使用 hash。
- 酷狗 hash／audio_id 不假定为 ChKSz ID。解析缺失文件时，从 ChKSz 搜索结果取得其自身 ID，匹配同一 hash；没有 hash 确认时，必须唯一匹配标题、歌手、专辑及 2 秒内的时长。不同 hash、信息不足或歧义均拒绝。
- 带总数的分页路径在后续页失败、总数矛盾、缺失详情和重复分页时明确报错。酷狗专题 HTML 优先使用当前官方路由，兼容旧赋值形式；声明总数时严格校验，未声明总数且全局分页接口失败时仍无法证明没有隐藏截断，不能据此宣称所有专题页均可完整读取。

平台搜索与 ChKSz 解析都按原生音质值执行。全局偏好继承可做语义映射，例如 `lossless` 到 QQ／酷狗的 `flac`；任务显式填写时必须使用该平台合法值，不自动降级或转码。

## 网页与配置生命周期

首次 `serve` 缺少配置时创建 `tasks: []`，没有 Key 也能启动本地控制台。网页提供任务增删改、启用／禁用、立即同步、历史、搜索、歌单预览及有限全局设置；默认地址为 `127.0.0.1:8080`，只允许回环监听。

网页编辑使用 YAML 节点保留不相关字段和注释。候选配置写入原目录临时文件，经完整校验后原子替换；发布前比较原内容，发现外部编辑则返回冲突，不覆盖。任务 ID 不随编辑改变，删除任务不清理音频或数据库记录。

保存成功后重新安装 cron，并更新可选回退开关。运行中任务完成后才能编辑／删除；待执行任务使用最新配置并跳过已禁用／删除任务。手动编辑 YAML 没有自动监视，需要重启。数据库、监听、超时、环境变量名等非网页设置也需重启。

网页不接收 Key 或 Cookie。Key 延迟到真正解析或元数据回退时读取；原生预览／搜索、以及原生读取成功且文件均完整的同步可不提供 Key。可选平台 Cookie 与 ChKSz Key 分别从环境读取，互不转发，更换后重新启动进程。

## SQLite、文件与恢复

SQLite 内嵌在进程中，一个本地文件即可，无需部署额外数据库：`downloads` 以任务／平台／歌曲 ID 为联合身份，保存路径、大小、SHA-256 和歌曲元数据；`runs` 保存执行时间、状态与计数。schema 通过 `user_version` 管理，拒绝旧程序迁移更新版本数据库。

写进程持有操作系统锁；只读状态查询可以并行。文件名为 `平台-稳定ID.实际格式`，每个任务独立目录。完整本地文件按常规文件与大小检查跳过，不每轮重新哈希；同大小外部修改不属于当前检测能力。

缺失文件先解析再下载；已登记但大小异常的文件，仅在解析成功后保留为 `.corrupt-*`。下载写同目录随机 `.part`，检查响应长度和文件头，计算 SHA-256，以硬链接原子提交后登记 SQLite。目标文件系统需支持硬链接。崩溃后的未登记成品可恢复登记，但当前仍可能消耗解析请求；删除远端成员或任务均不删除成品。

## 调度、限流与停止

五字段 cron 使用全局 IANA 时区，每任务可覆盖表达式。单 worker 串行处理任务，合并同任务重复触发；默认启动不立即同步，停服错过的时间不自动补跑。

原生元数据和 ChKSz 使用独立请求间隔，默认分别为 1 秒和至少 3.1 秒。ChKSz 账户／额度等错误停止共享 Key 当前批次；429 仅在有效 `Retry-After` 下最多重试一次。不会无限重试、自动充值、跨平台替换歌曲或静默降低音质。

退出时停止调度、取消请求／下载，尽力登记结果，再关闭 HTTP、SQLite 和写锁。测试服务也必须自行结束并释放端口。

## 验证状态

普通全量测试、静态检查、构建和 `CGO_ENABLED=1 go test -race -count=1 ./...` 已通过。模拟测试覆盖直连零 ChKSz 请求、受支持回退、Key 延迟校验、文件缺失／重启增量、外部配置冲突和网页后端。普通开发脚本使用 `CGO_ENABLED=0`；竞态检查在可用本机 C 编译环境执行，没有修改系统工具链。实际 Go 服务的浏览器验收通过 67 项检查，覆盖桌面、375px 手机、横屏、键盘、9 次真实配置写入和真实进程重启；检索／预览 UI 使用明确的本地模拟响应。详见 [网页界面设计](Web界面设计.md)。

2026-11-20 已关闭元数据回退并清空 ChKSz Key，真实验证三平台歌曲搜索；网易云公开歌单 `3778678` 为 200/200，QQ `7217720898` 为 35/35。酷狗官方专题 `id_1067062` 读取 20 首，另经官方移动页面 `songcount=20`、`total=20` 独立佐证。没有 ChKSz 或音频请求。这些样例不覆盖私有／受限歌单、大歌单及酷狗全部 ID 家族。

个人 ChKSz Key 与真实音频下载尚未联调；酷狗原生身份与 ChKSz 搜索结果的匹配目前由模拟数据验证。没有 Docker 打包、公网部署、真实 Linux 运行或代码推送的完成声明。
