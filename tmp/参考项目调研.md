# 参考项目调研：歌单、搜索与音频解析分离

更新日期：2026-11-20（Asia/Shanghai）

## 当前结论和实现

两个参考工程都通过音乐平台自身的元数据接口读取歌单、搜索和歌曲信息，自定义音源只负责取得音频地址。Meloport 已按这个分工实现原生来源适配，不能再把“ChKSz 没有 QQ／酷狗歌单接口”作为不接入它们的理由。

正式支持网易云、QQ 音乐、酷狗；其他平台只保留扩展接口，不注册未实现来源。默认路径为：平台歌单／搜索 → 本地缺失检查 → ChKSz 音频解析 → 下载。原生成功时不再请求 ChKSz，缓存完整的同步也不预先要求 Key。

可选元数据回退仅在直连失败后执行：网易云歌单及三平台歌曲搜索有文档化 ChKSz 接口；QQ、酷狗歌单没有，不编造替代路径。可通过 `metadata.fallback_to_api: false` 关闭可选回退。酷狗解析前为取得 ChKSz 自身 ID 的确认搜索属于音频解析流程，不受该元数据开关控制。

## 网易云

参考位置：

- `server/src/modules/utils/musicSdk/wy/songList.js:33-67`：链接解析。
- 同文件 `69-125`：通过 `api/linux/forward` 封装 `/api/v3/playlist/detail`。
- `server/src/modules/utils/musicSdk/wy/musicDetail.js:62-79`：批量 `/weapi/v3/song/detail`。
- `server/src/modules/utils/musicSdk/wy/musicSearch.js:24-32,45-56,71-79`：歌曲搜索及数据提取。

关键约束是 `playlist.trackIds` 表示完整成员，`playlist.tracks` 可能只包含部分详情。Meloport 独立实现协议封装，校验全部成员并有界补取缺失详情；不能仅凭 HTTP 200 或非空 tracks 认定完成。搜索同样走网易云协议。

若原生歌单最终失败，允许回退到 ChKSz `/api/163_playlist`。回退解码仍保留有限封装兼容，并沿选中路径校验总数及 `trackIds`／`track_ids`；不能通过回退将不完整数据误报成功。Key 不出现在平台请求中，平台 Cookie 也不传给 ChKSz。

## QQ 音乐

参考活动实现为 `server/src/modules/utils/musicSdk/tx/songList.js:392-449`：POST `u.y.qq.com/cgi-bin/musicu.fcg`，模块 `music.srfDissInfo.aiDissInfo`、方法 `uniform_get_Dissinfo`，使用 `disstid`、`song_begin` 和 `song_num`。同文件注释中的 `CgiGetDiss` 是旧实现，不能误当活动协议。

响应主要是 `req_1.data.songlist`、`total_song_num`、`dirinfo`。歌曲字符串 `mid` 与数值 `id` 不同，参考字段规范化见同文件 `451-468`。Meloport 使用 MID 作为稳定歌曲身份，独立实现固定页大小串行读取，验证总数与重复页；随后仅为缺失文件将 MID 交给 ChKSz。

搜索观察来源为 `server/src/modules/utils/musicSdk/tx/musicSearch.js:95-134,142-168`，采用 `music.search.SearchCgiService` 的桌面搜索协议；Meloport 已有对应原生适配。原生歌曲搜索失败可选回退 ChKSz QQ 搜索；歌单没有 ChKSz 回退。

## 酷狗音乐

参考将以下身份分开，不能相互猜测替换：

- `server/src/modules/utils/musicSdk/kg/songList.js:838-852`：纯数字是分享码，`id_...` 是专题 ID，完整链接走相应分支。
- 同文件 `523-559`：`global_collection_id + chain` 走签名 `/v2/zlist/list`，固定每页 50。
- 同文件 `570-590`：另一类全局歌单走 `special/info_v2`、`song_v2`。
- 同文件 `109-131`：专题读取平台网页内嵌成员。
- 同文件 `283-325,1016-1027`：成员 hash 批量补齐歌曲元数据。
- `server/src/modules/utils/musicSdk/kg/musicSearch.js:21-23,60-74,96-115`：原生搜索同时返回 `Audioid`、`MixSongID` 和 `FileHash`。

Meloport 独立实现签名请求、分享码／gcid／chain 分流、固定分页和详情补齐。chain 分支每页 50、最多 100 页，全局歌单每页 100、最多 100 页；出现缺失页、总数变化、重复页或无法补齐的成员时失败。

2026-11-20 的真实公开网页检查发现参考里的旧 `www2.kugou.kugou.com` 路由不可用，当前官方专题页使用 `var data=[...]` 和 `var specialInfo={...}`，且数据声明后可能用逗号继续其他声明。Meloport 已优先使用 `www.kugou.com/yy/special/single/{id}.html`，用 JSON 解码器读取指定赋值后的数据，不执行脚本，兼容旧 global.data 形式；完整内嵌歌曲信息可直接复用，减少额外元数据请求。有声明总数且详情完整时无需额外请求；否则在可取得 gcid 时先尝试全局分页路径，失败再使用平台内嵌列表。

酷狗原生 hash／audio_id 不假定是 ChKSz `id`。仅进入缺失音频解析时才请求 ChKSz 自身搜索结果：相同 hash 优先；否则要求唯一的标题、歌手、专辑及时长（容差 2 秒）匹配。明确不同 hash、信息不足和歧义拒绝，不自动换成同名歌曲。

专题页声明的 `songcount`／`song_count`／`count`／`total` 与成员数矛盾时失败；达到内嵌列表上限时明确失败。本次公开样例 specialInfo 没有歌曲总数字段，仅靠 HTML 仍无法证明不存在隐藏截断；样例完整性另外由官方移动 JSON 的 `songcount=20`、`total=20` 佐证，不能推导所有专题页均可完整读取。不透明短链接暂需用户先展开。

## 分页与失败处理

参考中的两种处理应区别：

- `server/src/server/integrations/subsonic.ts:2444-2465` 有界读取、拒绝后续空页并检测重复页，适合借鉴。
- `server/src/server/task/networkListTask.ts:198-225` 后续失败后退出循环，随后仍以局部列表覆盖原列表，不适合本服务的完整成功判断。
- `server/src/server/server.ts:6515-6559` 的搜索有串行分页、ID 去重及预算控制，但其中具体平台深度和条数仅是当时实测，不是固定保证。

原生 HTTP 共享响应大小限制、JSON 大整数保留、重复字段拒绝、超时与取消、串行请求间隔。只请求已归一化的平台地址；不执行参考中的任意链接抓取或无限重试，不自动跨平台搜索替代原歌单成员。
